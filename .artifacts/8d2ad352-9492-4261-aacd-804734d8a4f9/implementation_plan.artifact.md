# Architectural Upgrades Phase 2: Serialization, ANR WatchDog, Coil, DataStore & Graph Visualization

## Goal
Implement the top recommended industry libraries (`kotlinx.serialization`, `ANR-WatchDog`, `Coil`, `DataStore`) into AutoTap, ensuring absolute backward compatibility for existing exported/imported JSON scenarios and metadata.
Additionally, establish an ecosystem approach to understanding codebase relationships (Dependency Graphing).

## Proposed Additions & Tools

### 1. `kotlinx.serialization` (JSON Parity & Safety)
- Add `org.jetbrains.kotlin.plugin.serialization` and `kotlinx-serialization-json` to Gradle.
- Create `@Serializable` wrapper classes for `TemplateMetadata` and `MacroScenario` that seamlessly map to the exact JSON keys currently generated by `org.json.JSONObject`.
- **Compatibility Guard:** We will keep the legacy `org.json` parsers as a fallback layer during import. If serialization fails, the app will gracefully degrade to legacy parsing to guarantee old backups still work.

### 2. `ANR-WatchDog` (Thread Safety Monitor)
- Add `com.github.anrwatchdog:anrwatchdog` to Gradle.
- Initialize it in `AppLogger.init()` to route any `ANRError` directly to the `error_log.txt` and `LogViewerDialog`, empowering the developer to instantly see if OpenCV or ML Kit is choking the UI thread.

### 3. `Coil` (Asynchronous Image Loading)
- Add `io.coil-kt:coil` to Gradle.
- Replace synchronous `BitmapFactory.decodeFile` in `EditActionDialog` carousels with `ImageRequest` loading, dramatically improving overlay scroll performance and eliminating OOM risks in large folders.

### 4. `Preferences DataStore` (Modern Async Settings)
- Add `androidx.datastore:datastore-preferences` to Gradle.
- Migrate the synchronous `SharedPreferences` (e.g., `PREF_GLOBAL_CLICK_DURATION`, lock screen settings) to an async DataStore repository hooked into `AutoTapOrchestrator` via Coroutine flows.

### 5. Dependency / Architecture Visualization Tooling
> "есть библиотеки чтобы отслеживать взаимосвязи в коде, чтобы изменения учитывали весь контекст кода или сделать это через модуль питон?"

Yes, rather than bloating the Android app with a library for this, this is best solved via tooling.
- **Python Module:** We will create `1AInspector/generate_architecture_graph.py`. This script will parse all `.kt` files, extract class dependencies, imports, and interface implementations, and generate a Mermaid diagram (`architecture_graph.artifact.md`) or a Graphviz `.dot` file. This gives you a clear visual map of how `Orchestrator` -> `Manager` -> `Engine` interact, preventing regressions when modifying core code.

## User Review Required

> [!WARNING]
> Implementing `kotlinx.serialization` and `DataStore` requires refactoring the import/export flow and how settings are read at startup. While backward compatibility is a priority, modifying the data layer is the highest-risk operation in Android.

> [!IMPORTANT]
> The architectural dependency graph script will generate an artifact you can view. Do you want it to output a `Mermaid` diagram (viewable natively in GitHub/Markdown) or a `Graphviz (.dot)` file (better for giant projects, requires external viewer)? I will default to Mermaid unless you specify otherwise.
