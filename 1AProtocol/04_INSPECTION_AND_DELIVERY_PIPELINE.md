# 1AProtocol: 04. СИСТЕМА ИНСПЕКЦИИ, АВТОЛЕЧЕНИЕ И СБОРКА

## 1. ПРИНЦИП АКТИВНОГО САМОЛЕЧЕНИЯ (INSPECT & AUTO-HEAL)
- Модули в `1AInspector/check_*.py` реализуют сигнатуру `run_check(root_dir: str) -> tuple[bool, str]`.
- Инспекторы обязаны не только фиксировать нарушения, но и автоматически накладывать восстановительные патчи.
- Допускается строго 1 цикл ограниченного автолечения (Bounded Remediation) для исключения взаимной деградации чекеров.

## 2. КОНВЕЙЕР МАСТЕР-СБОРЩИКА (1ABuild.py)
Запрещен ручной разрозненный запуск. Пайплайн выполняется строго в 4 фазы:
1. Запуск инспекторов `1Ainspector.py` с автоисправлением.
2. Юнит-тестирование: `gradlew :app:testDebugUnitTest` (гарантия Zero-Regression).
3. Компиляция APK: `gradlew :app:assembleDebug --console=plain`.
4. Доставка на устройство (`1AAutomation/adb_deploy.py`):
   - **Hardware Serial Pinning**: привязка выполняется по аппаратному `ro.serialno` (или файлу `.target_serial`).
   - mDNS-службы беспроводной отладки (`_adb-tls-connect._tcp`) от других компьютеров строго фильтруются.
   - Устройство подключено: `INSTALLED_AND_LAUNCHED` (Код 0).
   - Устройство отсутствует / оффлайн: `NO_DEVICE_CONNECTED` (Код 0, сборка и тесты считаются полностью успешными).
   - Ошибка установки (например, несовместимость подписи): код ошибки ADB с подсказкой.

## 3. СТРОГИЙ АУДИТ И СИНХРОНИЗАЦИЯ (1AZapros.md)
- Каждая операция фиксируется в журнале с отметкой времени, описанием первопричины и вердиктом верификации на русском языке.

## 4. КОНТРАКТ АВТОМАТИЧЕСКОГО ПУША В GITHUB (AUTOMATIC GITHUB PUSH CONTRACT)
- После прохождения фаз сборки и верификации инспекторами инструмент отправки/скрипт сборки ОБЯЗАН автоматически выполнить синхронизацию с удаленным репозиторием GitHub (`git add -A && git commit -m "..." && git push`).
- Пуш выполняется в целевую ветку (`main`, `1Gemini` или текущую активную ветку `HEAD`).
- Автоматический push гарантирует отсутствие расхождений между локальной рабочей директорией и репозиторием GitHub.
